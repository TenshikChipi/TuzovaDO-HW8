## Задание 1.2

| Утверждение | Abstract class | Interface |
|---|:---:|:---:|
| Может содержать поля с конкретными значениями | + | − |
| Может иметь полноценный конструктор | + | − |
| Один класс может наследовать/реализовывать несколько таких типов | − | + |
| Может содержать реализацию метода по умолчанию | + | + |
| Может объявлять свойства без реализации | + | + |
| Может быть использован как тип поля или переменной | + | + |
| Может наследовать классы | + | − |
| Может содержать приватные методы | + | + |

### Объяснения

1. **Поля:** абстрактный класс может хранить состояние объекта, а интерфейс не может содержать обычные поля экземпляра
2. **Конструктор:** у абстрактного класса может быть конструктор, у интерфейса обычного конструктора нет
3. **Множественное наследование:** класс может наследовать только один базовый класс, но реализовать несколько интерфейсов
4. **Реализация методов:** абстрактный класс может содержать готовые методы, а интерфейс поддерживает методы с реализацией по умолчанию начиная с C# 8
5. **Свойства:** оба типа могут объявлять свойства, реализацию которых предоставляют наследники или реализующие классы
6. **Тип переменной:** оба можно использовать как тип переменной, которая ссылается на объект подходящего класса
7. **Наследование:** абстрактный класс может наследовать другой класс, а интерфейс — только другие интерфейсы
8. **Приватные методы:** оба типа поддерживают приватные методы. В интерфейсе они используются как вспомогательные методы для реализаций по умолчанию

### Дополнительный вопрос

Я бы создала абстрактный класс `GameEntity`, содержащий общие свойства Name, HP и метод TakeDamage`

Схема наследования:

```text
GameEntity (abstract)
│
├── Player : IInteractable, IHealable
│
├── Enemy
│
└── NPC : IInteractable
```

**Интерфейсы:**

- IDamageable — получение урона (реализуется в GameEntity)
- IInteractable — взаимодействие с игроком
- IHealable — восстановление здоровья

Абстрактный класс нужен, поскольку у всех персонажей есть общее состояние и поведение. Интерфейсы описывают отдельные возможности: Player и NPC могут взаимодействовать, а восстанавливать здоровье умеет только Player. Такой подход позволяет не дублировать общий код и добавлять новые возможности без изменения всей иерархии классов.
